# SOP — 高保真前端工程的流程与门禁

本文件把 merps.co 这一轮（以及上一轮 aozi 的失败对照）沉淀成可执行流程。

- **Part A** 复刻一个已有网站（有外部真值）
- **Part B** 给素材 + `design.md` 从零自建前端（真值必须自己造）
- **Part C** 多 Agent 协作的取舍
- **Part D** 清单与反模式

技术标识符、路径、命令一律**逐字保留**，可直接复制执行。

> **本轮成本对照**：上一轮（aozi）因为跳过下面的 A2，付出了**两次整体返工**；本轮从 Gate 0 起步，
> 只在实现阶段发现 5 个可定位的缺陷，且全部在写代码期间就被工具抓住，没有一次返工。

---

## 0. 三条铁律

写在最前面，因为违反它们不会立刻报错，只会安静地浪费几天。

1. **基准不可离线重测 → 不许写一行实现代码。**
   "我看过那个网站"不是基准。基准的定义是：**别人可以重跑、并且拿到和你一样的数字**。
2. **验收标准必须是一条命令，禁止形容词。**
   "还原度高"不可执行；`sweep.py --mode geom` 输出 `rect <=0.75px 100.00%` 可执行。
3. **自我报告不算证据，尤其是我自己的。**
   任何"已完成/已修复"都要有可复跑的输出行、哈希或截图支撑；报告功能状态前先 `git status`。

## A1 侦察 — 先搞清楚目标"是什么"，再决定怎么抄

**不要一边看一边写。** 侦察的产出是一张事实表，不是代码。

逐项记录（每项都有对应的坑）：

| 项 | 为什么重要 |
|---|---|
| 路由清单（含 404 的路由） | `/privacy` `/terms` 上游就是 404，要记下来，别自己补 |
| 技术栈 / 是否预渲染 | 预渲染 = 可以直接对 SSR HTML 做机械移植；纯 CSR = 需要先跑浏览器 |
| **布局是阶梯式还是流体式** | merps 的 `--fluid-slope` 在 375–1600px 连续插值 → **只测 1440/375 会漏**，必须补 768/1024/1280 |
| 主题机制 | `html[data-theme]` + localStorage key（merps 是 `merps-theme`）→ 主题是独立的一维，必须逐主题测 |
| 素材形态 | merps **零位图**：logo 是 inline `mask-image`，其余全是 inline `<svg>` → 资产审计的扫描面不同 |
| 字体 | 可能跨域托管（merps 的字体在 `aspensearch.com`）→ 必须本地化 |
| 动效库与常数 | 库**名字和版本号常常就写在目标的 bundle 里**（merps 里就是 `1.3.26`）→ 不用猜 |
| 外部数据面 | 逐个实测可达性，别假设 |

**抓取要在有出网的环境里做**（本轮用的是 Composio 远程沙盒；本机出网是白名单制，直连目标站会 TLS reset）。

产出：`docs/DATA_SOURCES.md`（数据面 / 真实上游 / 可达性 / mock 边界）。

> 而且是**他们自己的后端在响应里写出来的**（`"source":"dexscreener"`）。

## A2 Gate 0 — 冻结真值（本轮最重要的一步）

### 做什么

```
capture（水合 DOM 存档）
  └─> build_offline（生成可离线渲染副本 reference/site/）
        └─> audit_assets（资产引用存在性审计）
              └─> shoot_baselines（逐路由 × 视口 × 主题 全页基准）
                    └─> gate0.py（门禁报告）
```

```bash
python3 tools/audit_assets.py                 # 必须输出 TOTAL MISSING: 0
python3 tools/build_offline.py --ref reference --out reference/site
bash tools/shoot_baselines.sh
python3 tools/replkit/gate0.py --ref reference --offline-dir site \
    --public-root reference/site --width 1440
```

### 为什么必须要"可离线渲染"

有 JS 的目标站，基准只能是**我们自己冻结的一份**。副本要满足：

- 抹掉 JS 与框架脚本（水合状态本来就是我们要复制的目标状态，不需要它再执行一遍）；
- 资源全部指向本地（图片/CSS/字体）；
- 保留目标的**全部布局变体和主题变体**（merps 是 `html[data-theme]` + 断点；
  上一轮 aozi 更极端：**同一份 HTML 里并行渲染 4 套布局**，靠断点显隐）；
- 每页自带的内联 `<style>` 必须跟页走（不同路由的内联样式不同，别只抓一份）。

### 本轮 Gate 0 抓到的真实缺陷（这一节是整份 SOP 的价值核心）

第一遍 Gate 0 报的是 **`[ok] offline assets resolve — 6/6 on disk`**，并断言
"every asset the DOM and the manifest reference is present"。**那是错的。**

`/logo.png` 通过 inline `style="mask-image:url(/logo.png)"` 被**每条路由引用 8–12 次**。
它由站点根提供服务，因此**不出现在任何清单条目、也不出现在 `<img>`/`<link>` 里**。
离线副本从 `reference/site/` 提供服务，那里没有这个文件 → 掩码失败 → **基准自己坏了**：

| 区域 | 坏基准 | 修好后 |
|---|---|---|
| 顶栏品牌标 34×22 | **1 种颜色**，一块纯色 `rgb(35,35,35)` | 104 种颜色，真实字形 |
| hero 水印 249×319 | **1 种颜色**（什么都没画） | 9 种颜色，真实字形 |

**危险在哪**：照着这个基准复刻出来的站，会忠实地把 **MERPS logo 抄成一个纯色方块**，
而像素比对会报 **100% 一致** —— 因为复刻体继承了同一个坏掉的掩码。

> **自洽的基准不能证明任何关于目标的事。** 这是本 SOP 里最贵的一句话。

修完之后，`gate0.py` 自己也有两个洞要补（已补）：

1. 离线资产扫描只匹配 `src|href|srcset|poster` 属性 → 现在**也扫 `url(...)`**
   （掩码失败是资产失败，不是样式选择）；
2. `resolve()` 对**裸文件名**返回 `None`，于是 `url(logo.png)` 被**静默跳过**而不是报缺失
   → 裸名现在按文档根解析。

**门禁自己会撒谎。** 每次它报"全绿"时，问一句：它**扫到了什么范围**？

### 入库边界（提前定，别留到最后变成悬空遗留项）

- **入库**：原始抓取件、归档资产、构建报告、工具、基准 manifest、缺陷证据图。
- **不入库**：`reference/site/`、`reference/screenshots/`、`build/` —— 一条命令可重生成。
  但**把它们的 sha256/尺寸钉进 `reference/baselines.json`**，这样"重生成的基准"能和
  "当初用来验收的基准"对上。（上一轮就是把这件事拖到最后，变成了悬空项。）

## A3 契约层 — 把边界写下来，不要靠记忆

| 文档 | 写什么 | 反面 |
|---|---|---|
| `SCOPE.md` | **逐路由状态策略**：哪些能像素比、哪些只能结构比、哪些照抄门禁态 | 为了让数字好看，把不可比的路由也塞进"像素 100%" |
| `PORT.md` | 机械移植规则、手写缝隙清单、**有意的差异及理由**、确定性 | 差异不留痕，下一个人以为是 bug |

这个差异在写代码**之前**就声明了，所以后面没有任何返工。

## A4 实现层 — 机械移植 + 窄缝手写

**规则：能生成的就不要手抄。** 每路由约 1400 个元素，手抄**无法验证**；生成则可以。

```
captured DOM
   │ gen_app.py（机械：DOM -> TSX，经 replkit/html_to_jsx.py）
   ▼
src/gen/parts/*.tsx      每个不同 markup 片段一个组件
src/gen/routes.tsx       每路由的 body 序列 + title/description
   │ 手写（只有需要数据的地方）
   ▼
src/desk/*.tsx           行情列表、图表面板、区间选择器
src/lib/*                sx()、theme、router、菜单 store
```

具体纪律（每条都对应一个真实缺陷）：

- **内联样式原样透传。** 目标把随主题变化的颜色**内联**（亮/暗是两套独立颜色，不是 CSS 变量），
  手抄必然漂移。`sx()` 把抓到的 style 字符串解析成 React 要的对象，**保序**并保留自定义属性（`--sbw`）。
- **chrome 按内容哈希去重，不要按假设。** merps 的 header 按内容哈希是 **3 个变体**
  （上下文 CTA 不同：首页 `Start trading`→`/trade`，应用内 `Trade options`→`/trade/options`）。
  想当然共用一个 header 就是错的。
- **文本逐字保留。** 折叠空白/丢弃纯空白文本节点，会让 header 渲染成 `Markets...`
  而目标是 `Markets ...`（那个空格挨着一个 SSR 注释 `Markets<!-- --> `）。
  **当时计算样式仍然 100% 一致**，只有一个 span 宽了 5px。这是"样式全绿但内容已经错了"的经典形态。
- **挂载点必须与目标一致。** 目标 `<body>` 直接放 header/main/footer；React 挂到 `#root`
  会插入一层树深 → 比对时把**错位的元素**互相比 → 几何只有 **44.87%**，还报"worst drift 9380px"。
  改挂 `<body>` → 100%。（**假阳性比没测更危险**：它会让你去修不存在的问题。）
- **数据区做成带断言的槽位。** 抓下来的 DOM 里是"未选中"占位符（`Loading markets...`、
  `div.desk-chart-empty`），生成器把它们换成具名 `<x-slot>`，应用来填，**并断言数量**，
  这样漏填或重复填不可能静默通过。目标只在图表存在后才渲染的控件（区间选择器）
  用**追加**而不是替换。
- **交互接线也生成**，锚点用目标**自己的** `aria-label` / class（`aria-label="Toggle theme"`、
  class 含 `desk-search`），**不新增 DOM 属性** —— 树要保持逐字节可比。
- **派生状态可以被推导，但必须标注为未验证。** 移动菜单的展开态抓不到（抓到的永远是闭态），
  从闭态推导（transition 时序包含逐链接 stagger 原样保留），并在 `VERIFICATION.md` 里
  **明确写成"未与目标比对"**。
- **生成器必须无状态/无时间戳**，按内容哈希命名 → 干净沙盒重跑逐字节相同。
- **派生且内嵌宿主机绝对路径的产物不要入库**（`site_build_report.json` 曾导致
  两台机器、同样内容、**树哈希不同**）。

### 本轮由工具抓出的 5 个真缺陷（截图审查一个都发现不了）

| 缺陷 | 表现形式 | 修法 |
|---|---|---|
| React 挂在 `#root` | 几何 44.87%，比对错位 | 挂 `<body>` |
| 纯空白文本节点被吞 | span 窄 5px，样式仍 100% | 文本逐字保留 |
| 离线副本 `url(logo.png)` 变相对路径 | 非根路由 404，掩码 logo 画成**实心块**，7922 差异像素 | 生成器改根绝对路径 |
| 流水线假设 `build/` `app/src/data/` 已存在 | 本地能跑，**干净克隆必挂** | 每个脚本自建输出目录 |
| `site_build_report.json` 入库 | 树哈希不一致 | 取消入库 + gitignore |

## A5 测量层 — 四层，缺一层就有盲区

### 矩阵

**路由 × 视口（1440 / 375 / 中间宽度 768·1024·1280）× 主题（light / dark）**
流体布局的站，中间宽度**必须**采；主题**是独立一维**，不是"顺手看看"。

```bash
python3 tools/replkit/sweep.py --config replkit.json --mode geom  --all
python3 tools/replkit/sweep.py --config replkit.json --mode pixel /:1440 /:375
python3 tools/replkit/sweep.py --config replkit.json --mode text  /:1440
python3 tools/verify_settled.py          # 结构层
```

### 四层各管什么

| 层 | 工具 | 抓的是 |
|---|---|---|
| 1 几何 + 计算样式 | `measure.py` + `compare.py` | tag / class / rect ≤0.75px / computed style |
| 2 像素 | `shoot.py` + `pixel_diff.py` | 全页像素（`--absolute-bg --freeze`，注意拼接带） |
| 3 **文本** | `textdiff.py` | **上一轮完全缺失的一层**：当年 254 处文本错误藏在绿色的几何报告后面 |
| 4 结构（结算态） | `verify_settled.py` | 对"浏览器结算后"的抓取比 tag/class/`data-active`/单元格文本 |

**定位工具比新数字更重要**：`localize_diff.py` / `classify_drift.py` 把偏差**归因到具体子树**。
数字变红时不要"再改改看"，要先回答"**哪一个元素**"。
（本轮就是靠它把 `/` 的残余精确归因为 4 个 hero 硬币元素 + 8 个 `#clients` 标题元素。）

### 禁则

- **不许"更新快照让它变绿"。** 基准是冻结的契约，不是可以随时重拍的参考照片。
- 数字变绿之前，先确认**门禁的扫描范围**（见 A2 的 `/logo.png`）。
- 无法测量的项，写"未验证"，**不要估算**。

## A6 动效层 — 行为断言，截图看不见

### 从目标自己的产物里读参数，不要猜

本轮的答案全都在目标的 bundle 里：

| 效果 | 实现 | 关键常数（逐字来自目标 bundle） |
|---|---|---|
| 滑动阻尼 | **Lenis**（版本号就写在他们产物里） | `1.3.26`，`duration: 1.1`，`t => 1-(1-t)³`，`smoothWheel: true` |
| 文字渐入 | 他们自己写的 `IntersectionObserver`（不是库） | 初始 `translateY(110%)`/`opacity 0` → `transform 900ms cubic-bezier(0.16,1,0.3,1) Dms, opacity 450ms linear Dms`，**同组每行 70ms 递延**，`rootMargin '0px 0px -12% 0px'`，`threshold .1` |
| 计数器滚动 | 同上 | `1400ms`，同级 `90ms` 递延 |
| 其他 | `#clients` 跟随视口中心、硬币 20s 无限、跑马灯、主题横扫 | —— |

除 `lenis` 外**没有引入任何新依赖**。

### 验证方式

```bash
python3 tools/verify_motion.py       # 22 checks
python3 tools/verify_counters.py     # 6 checks
```

断言的是**行为**（截图看不到）：滚轮是被阻尼的（34 个不同中间位置，而不是瞬跳）、
折行以下的文字**初始隐藏**且**视口内一个都不藏**、缓动字符串与目标一致、递延是 70ms 的整数倍、
计数器**穿过 13 个中间帧**滚到目标位。

### 本轮只有行为探针能发现的缺陷

**统计数字滚上去再跳回 0。** 原因：我们把"原始内联样式快照"取在了**把该列强制归零之后**，
然后 1.46s 后又把这份快照写回去。目标从不 restore。
**因为像素基准保存的是正确数字（注水前渲染），任何像素比对都不会指向它** ——
必须先分类异常元素、再探测"滚动到底之后"的实际状态才能定位。一行修复，几何 96.79% → 99.14%。

### 必须声明的代价：口径会变

冻结基准是**无 JS 的注水前渲染**，而开了动效的复刻体会水合。
**要实现动效，就不可能对它逐像素全等** —— 两者互斥。宣称为：
"以前那句 100.000%（0 差异像素）作废"，并**逐项归因**：

| 路由 | 视口 | 差异像素 | 归因 |
|---|---|---|---|
| `/` | 1440 | 120 508 | 119 009 = `#clients` 激活步骤面板；~1 480 = 顶栏旋转品牌标；**其余 0** |
| `/portfolio`、`/list-token` | 1440 | 各 **296** | 148 px × 2 拼接带 = 顶栏旋转标；两条路由计数相同，互相印证 |

交叉验证：95% 的差异落在**纯色区域**（梯度 <2）→ 是面板换色而非字形抗锯齿。
**没有归因的差异数字是不负责任的红字。**

### 一条教训

动效代码当时**写好了但从未提交**（`lib/motion.ts` 未跟踪，`HEAD` 还停在旧交付提交），
所以我一度以"已实现"汇报，实际线上没有。**报告功能状态前先 `git status`。**

## A7 交付层

### 推送（本地没有凭据时）

本地 `git push` 不可用时，走**远程沙盒 + 逐片校验**：

```bash
python3 tools/replkit/xfer.py pack     --in <payload.tar.xz> --slices /tmp/s --size 8000
python3 tools/replkit/xfer.py manifest --slices /tmp/s --manifest /tmp/s/manifest.json
python3 tools/replkit/xfer.py verify   --in <rebuilt> --slices /tmp/s --manifest /tmp/s/manifest.json
```

- 载荷 `xz` + base64，**8K 一片**，**每片 md5**，**末端整包 sha256**；
- 提交在沙盒内用 `run_composio_tool(GITHUB_COMMIT_MULTIPLE_FILES)`（`encoding: base64`），
  **字节不经过模型**；
- 提交后比对**树对象哈希**（本地 `HEAD^{tree}` vs 远端），而不是"看提交成功了"。

> **真实事故**：有一片 **4000 字符只写入 3999**（少 1 个字符）。
> 逐片 md5 当场拦下 → 用 50 字符前缀校验逐段二分 → 定位到具体偏移 → **只补发那 50 字符拼接修复**。
> 整包 sha256 最终与原文件完全一致。
> **没有逐片校验，就会得到一个坏文件而毫无察觉。**

### 部署与线上核验

1. 建 Vercel 项目（`rootDir` 指向 app，Vite）；
2. **按 commit sha 部署**（`gitSource: {type:github, repoId, ref:'main', sha}`），轮询到 `READY`；
3. **回抓线上资产重算 sha256**，与"本地已通过全部验证的那份 `dist`"比对：
   `identical: 23/23`、`assets/index-JOTZnwNw.js` 463 924 字节且哈希相同
   → 证明"线上跑的就是被验证过的那份构建"；
4. 每条路由的状态码。

### 可复现性的最强证明

**干净克隆 → 只覆盖手写源码 → 跑一遍提交的流水线 → 全树逐字节比对。**
本轮：**128 个非 lockfile 路径全部逐字节相同**，产物 bundle 哈希也相同。
这是唯一能证明"流水线真的能重建交付物"的方式。

### 交付卫生

- 破坏性操作（force push、删库重建）**先停下问**；
- **有未提交改动时，绝不要 `git reset --hard origin/main`**（本项目两次被它静默回滚）；
- 保留足量磁盘（Chromium 在 <200MB 时会崩，`/tmp` 会被 PNG 灌满）。

# Part B — 没有目标站：给素材 + `design.md` 自建前端

标记说明：**[复用]** = 本轮已验证的直接复用；**[外推]** = 由复刻经验推导、尚未在本项目验证。

## B1 根本差异与它带来的第一个动作

| | 复刻 | 自建 |
|---|---|---|
| 真值 | **外部、免费、已经存在**（网站） | **必须自己创造并冻结** |
| `design.md` 的地位 | —— | **是规格，不是真值** |
| 失败模式 | 不看 DOM，凭印象抄 | **把散文规格当成真值** |

**散文规格 ≈ 二手描述 —— 这正是上一轮整体返工的成因**（一个 bot 把"照这个页面做"当规格，
忠实实现了一份错误的页面）。所以第一个动作不是写代码，而是：

> **把散文变成机器可校验的契约；无法变成契约的地方，列出来交给人裁决。**

**[外推]** 具体地，开工前产出 `docs/CONTRACT.md`：tokens（机器可读）+ 组件清单 + 状态矩阵 +
断点策略 + 文案稿 + 每条 ticket 的验收命令。**这份文件是自建项目的 `reference/`。**

## B2 等价映射（照搬 A 段的骨架）

| 复刻里的一环 | 自建里的对应物 | 状态 |
|---|---|---|
| 目标站 | `design.md` + 素材包 + 文案稿 + API 契约 | **[外推]** |
| 抓取的水合 DOM | `tokens.json` + 组件/状态清单（机器可读） | **[外推]** |
| 离线可重测基准 | **首个获批构建 = 批准快照**（视觉回归基线） | **[外推]** |
| `DOM → TSX` 生成器 | tokens → CSS 变量/主题层生成；图标 → 组件生成 | **[外推]** |
| 四层测量 | 见 B4（保留 3 层 + 新增 4 层） | 部分 **[复用]** |
| "不验证什么"成表 | 同样要有，而且**更需要**（无真值可比） | **[复用]** |
| Gate 0 | **Design Gate 0**（见 B3） | **[外推]** |
| 干净克隆重跑一致 | 同样适用 | **[复用]** |

## B3 Design Gate 0 — 开工前必须冻结的东西 **[外推]**

| # | 冻结物 | 为什么 | 缺失的后果 |
|---|---|---|---|
| 1 | **Design tokens（机器可读）**：颜色/间距/圆角/字号/行高/阴影/动效时长与缓动/断点/层级 | 单一来源；产物由脚本生成 | 组件里散落魔法数，主题改不动，还原度无从度量 |
| 2 | **组件清单 + 状态矩阵**：variants × states（default/hover/focus/active/disabled/loading/empty/error）× 尺寸 | **这份表就是自建项目的"DOM 真相"** | 少一个 state 就等于少做一块，且不会被任何人发现 |
| 3 | **断点策略**：阶梯式还是流体式 | 流体式必须采中间宽度（复刻已验证） | 只在两个断点好看，中间全崩 |
| 4 | **文案稿（逐字冻结）** | 文案是像素的一部分；改文案 = 改基线 | 基线反复漂移，"变红"无法解读 |
| 5 | **每条 ticket 的验收命令** | 形容词不可执行 | "做完了"变成主观判断 |
| 6 | **资产审计**：引用的 vs 存在的 | 复刻已验证这一类的代价 | 缺图 → 布局塌陷（复刻里表现为"图片高度为 0"的假回归） |
| 7 | **矛盾/空白清单** | 设计稿必然有缺口 | 自己猜 → 必然返工（V-01 的教训） |

第 7 条最重要：**design.md 里含糊或有内部矛盾的地方，交给人裁决，不要自己补。**
补出来的东西会变成后期返工，而且**没人知道那是猜的**。

## B4 测量层：从 4 层扩到 7 层

**保留（[复用]）**

1. **几何 + 样式** → 在自建里它的意义变成**布局契约检查**：间距是否走 scale、有没有任意值、断点是否符合策略；
2. **像素** → **批准快照 diff**（基线是"已获批的渲染"）；
3. **文本** → 对**文案稿**逐字比对（含空白）。

**新增（[外推]）** —— 这些都是自建比复刻更容易翻车、而上面三层**测不到**的地方：

4. **状态覆盖**：状态矩阵里的每个 state 都要有截图或 DOM 断言（loading/empty/error 尤其易漏）；
5. **交互链路**：关键流程 E2E（登录 → 下单 → 确认 …），断言**可见结果**而非内部状态；
6. **质量预算**：a11y（对比度、键盘可达、landmark/heading 顺序、axe 无 critical）、
   性能（bundle 预算、LCP/CLS）、**无水平溢出**、控制台零错误 —— 都要写成**数字门槛**；
7. **数据层契约**：API schema 校验 + mock 与真实响应同形（避免"接上真接口就崩"）。

断点矩阵与主题维度同 A5。

## B5 可以直接拿去用的（[复用]）

- **工具**：`measure.py` / `compare.py` / `pixel_diff.py` / `textdiff.py` / `sweep.py` /
  `localize_diff.py` / `xfer.py` / `gate0.py`（见 `shared/replkit/`）；
- **纪律**：先冻结基准、命令即验收、声明"不验证什么"、生成器确定性、干净克隆可复现、
  **偏差要能归因到子树**；
- **交付链路**：沙盒传输（逐片 md5 + 整包 sha256）→ GitHub → Vercel（按 sha 部署）→ 线上逐字节核验；
- **卫生**：先 `git status`、别 track 派生产物、破坏性操作先问、留足磁盘。

## B6 自建特有的风险与对策 **[外推]**

| 风险 | 复刻里为什么没有 | 对策 |
|---|---|---|
| 规格含糊/自相矛盾 | 有目标站可查 | 矛盾清单交人裁决；含糊处变成**显式默认值并标注** |
| 没有"正确答案" | 有 | 首个获批构建冻结为基线；此后每处偏差都要有**意图说明**，否则视为缺陷 |
| 范围蔓延 | 目标站天然限定范围 | **先垂直切片**（B7），再横向铺开 |
| 状态漏做 | 复制即可 | 状态矩阵当 checklist，脚本断言 |
| 素材权利/完整度 | —— | 审计 + 声明缺口，**不发明** |
| 质量无门槛 | 像素即门槛 | 明写 a11y / 性能 / 包体预算 |

## B7 垂直切片优先 **[复用+外推]**

先做**一个**页面/流程，但**全状态 × 全断点 × 全主题**，把 7 层测量跑通，再横向铺开。

- 复刻里的等价物：先用**一条路由**证明整条工具链（本项目就是先让 `/` 跑到 100%，再铺其余 4 条）；
- 自建里的额外收益：同时证明 **tokens、组件层、状态层、测量层**都是对的，
  避免"铺了 20 个页面才发现 token 体系错了"。

# Part C — 多 Agent 协作：什么时候值得，什么时候是负收益

## C1 实测净收益（本项目 + 上一项目）

| 委派 | 净收益 | 原因 |
|---|---|---|
| 抓取（真抓、接口窄） | **正** | 真值的地基。但它**转述的结论错了**（"只缺 1 张头像"） |
| 抓取（伪基准） | **负** | 直接导致两次返工 |
| QA 无基准打分（86% → 96.8%） | **负** | 无标准答案的打分 = **虚假置信**，比没有 QA 更危险 |
| QA 有基准独立复跑 | **正（高价值）** | 抓出 264 个真差异像素 + 指出我"不比对文本"的盲区 |
| QA 长任务超时 | **负** | 与其它 bot 争同一台机器，失败还是静默的 |
| dev 实现 + 精修 | **负** | 忠实执行错误规格 = **放大器** |
| 我自己（生成器 + 测量循环） | **正** | 核心价值几乎全在这里 |

## C2 判据（一句话）

> **只有单元接口窄到"不需要理解真值"、且输出可机器校验时，委派才不损失保真度。**

推论：

- **委派在方向错误时不是中性的，是放大器。** 错误方向 × 强执行力 = 比单干**更快**地偏离；
- **独立复核的价值 = f(可复现工具 × 已冻结真值)。** 两者都没有时，复核价值**为负**
  （同一角色，无基准时产出"没人能反驳"的假分数，有基准时一轮抓出真缺陷 —— **变量不是 agent**）；
- **信息每过一个 agent 衰减一次。** 最有效的委派接口窄到只需"抓这个 URL / 跑这条命令 / 回原始输出"；
  最无效的接口宽到等于"照这个页面还原"——那接口就是全部上下文，**无法交接**；
- **角色矩阵 ≠ 并行计划。** 建 dev/qa/fetcher 是**组织隐喻**（谁负责什么），不是**并行计划**。
  先画任务依赖图：复刻链几乎纯串行（真值 → 生成器 → 实现 → 测量 → 交付），
  且**实现与测量无法并行**（测量的对象就是实现的产物）；
- **共享脆弱资源会让并行退化成互相干扰**，且失败**静默**（`Connection error` / `timeout`），
  看起来像"agent 不给力"。

## C3 默认配置

**默认只有一个执行者。** 只在三种情况开 bot：

1. 我摸不到的资源/凭据（抓取、需要独立出网的环境）；
2. **真值 + 工具就位之后**的对抗性复核；
3. 已切分、且输出**可哈希校验**的批量作业。

**复核 bot 的委派书模板**（必须照此写）：

```
复现以下命令，回报原始输出行：
  <command 1>
  <command 2>
要求：
- 只报原始输出，禁止自评分、禁止"看起来不错"这类结论；
- 若命令失败，如实说明失败，不要估算；
- 主动攻击这两点：<已知盲区1>、<已知盲区2>
```

（本轮就是这么写的，于是拿到了 264 个真差异像素 + "工具不比对文本"这个盲区。）
